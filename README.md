# 行列双存同步组件

同一份数据同时写入行式存储（点更新）与列式存储（批量分析），通过异步变更队列保持两边最终一致，并提供一致性检查、单批次重建、崩溃恢复与运行统计。

```bash
./mvnw -q verify   # 一条命令编译并跑全部测试
```

## 架构

```
            ┌──────────┐  ChangeEvent(seq, pk, op, 整行镜像)
 写入 ────▶ │ RowStore │ ─────────────▶ ┌────────────────┐
            └──────────┘                │ FileSyncQueue  │  追加日志 + ack 水位（持久化）
                                        └────────────────┘
                                                 │ poll → apply → ack
                                                 ▼
                                        ┌────────────────┐     ┌──────────────────┐
                                        │  SyncWorker    │ ──▶ │   ColumnStore    │
                                        │ (异步消费线程) │     │ 按 batchSize 分批 │
                                        └────────────────┘     └──────────────────┘
                                                 │                      ▲
                                                 ▼                      │ rebuild(batchId)
                                          SyncStats ◀── ConsistencyChecker（行存为基准比对）
```

核心类（`com.example.gsb.sync`）：

| 类 | 职责 |
|---|---|
| `RowStore` | 按主键 insert/update/delete；每次变更分配全局递增 `seq`，先落本地再投递队列 |
| `FileSyncQueue` | 长度前缀追加日志持久化事件；`ack` 水位落盘；重启回放未 ack 事件，尾部残缺记录自动截断 |
| `ColumnStore` | 主键按固定大小分批；每批记录 `appliedSeq` 水位，重复事件幂等跳过；批次可独立重建 |
| `SyncWorker` | 异步消费：poll → apply → ack；支持 `drain()`/`awaitIdle()` 追平 |
| `ConsistencyChecker` | 范围比对，输出不一致主键与字段（`Mismatch`） |
| `SyncStats` | 同步条数、延迟分桶分布、不一致条数、重建次数、重复跳过数 |
| `DualStore` | 门面，组装以上组件 |

## 同步策略：延迟与一致的取舍

行存变更**同步落本地、异步投递列存**：写路径不等待列存，延迟低、可用性高；代价是列存存在毫秒级滞后（最终一致）。需要强一致读的场景可调用 `flush()`/`awaitIdle()` 追平后再读。事件携带**变更后整行镜像**，任意重放、乱序重放都幂等，这是崩溃恢复与重建合并不出错的基础。

## 一致性检查与判定窗口

逐行比对显然会把“还在传输中的正常延迟”误判为不一致，因此引入判定窗口：

- 行存每行记录最后变更 `seq`，列存每批记录已应用水位 `appliedSeq`；
  **行的最后变更 seq > 该批次水位 ⇒ 变更仍在传播窗口内，跳过不判**（删除同理，用主键的最后变更 seq）；
- `REBUILDING` 状态的批次整体跳过（查询本就返回旧批次）；
- 并发读写可能造成瞬时视图撕裂，任何候选不一致都要**二次稳定确认**（重读两边、行 seq 与批次水位均未变化且仍不一致）才计入结果。

## 批次重建

`rebuildBatch(batchId)` 只重建指定批次：标记 `REBUILDING` → 从行存取该批次主键范围快照 → 合并重建期间挂起（deferred）的变更 → 原子换入。重建期间查询**继续返回旧批次数据**，状态可通过 `getBatchStatus()` 观察；重建不阻塞行存写入，期间到达的变更不会丢失。

## 崩溃恢复

队列是 at-least-once：事件先持久化再消费，`ack` 在应用成功之后落盘。崩溃后重启用同一目录打开 `DualStore`，构造时自动回放 `seq > ackedSeq` 的事件补齐；已应用但未 ack 的事件会被重投，列存按批次水位幂等跳过（计入 `duplicateSkipped`），保证**补齐且不重复应用**。
